# 架构与维护

## 模块

- `main.js`：任务聚合、精确写回、计时、首页入口。
- `navigation.js`：知识与项目目录视图。
- `sidebar-nav.js`：所有工作台和 Markdown 阅读页共享的六项主导航、顺序与激活标记。每日推荐通过一次路由状态设置直达，避免先画本地论文列表再切换。
- `daily.js` / `daily-core.js`：记录整理、加密本地存储、Markdown 保存。
- `papers.js`：论文库、分类、摘要、选区操作与原生／React 挂载桥接。
- `paper-chat.tsx`：assistant-ui LocalRuntime、消息和输入组件、会话切换。
- `paper-chat-adapter.js`：现有 SSE 回调转异步生成器，适配 assistant-ui 模型接口。
- `paper-threads.js`：旧记录无损迁移、每篇论文的本地会话、草稿与回答分支。
- `arxiv.js`：官方 Atom API 查询、XML 解析、串行限流、缓存及版本归一化。
- `arxiv-view.js`：原生 Obsidian 搜索界面、结果展开、分类入库和已归档跳转。
- `paper-reader.js`：连续页占位、附近页面渲染、PDF.js TextLayer。
- `paper-core.js`：提取文字、引用校验、上下文选择。
- `paper-service.js`：论文数据持久化、MiniMax 请求与 PDF 文档缓存。
- `paper-stream.js`：HTTPS + SSE；UTF-8 分片、结束判断、AbortSignal、超时。
- `paper-layout.js` / `pdf-layout-worker.py`：独立翻译进程、版本化产物、失败保护。

## 问答路径

选区模式只提供选区和同页附近段落，上下文上限约 6,000 字符。全文模式选择相关段落，上限约 42,000 字符。均仅访问当前论文；附带近期对话，失败或取消的历史回答不再次作为模型事实上下文。

assistant-ui 负责创建消息、流式 Markdown、自动滚动、停止、复制和重试。模型适配器逐次 yield 完整的累计文本，完成后附上已校验的段落引用。生成过程不会重建 PDF 阅读区；离开聊天底部阅读时不强制追随输出。

每篇论文的 `assistantChat` 字段独立保存会话列表、当前会话、草稿和带 parentId/headId 的消息仓库。重试保留旧版本，BranchPicker 可切换回答。旧 `chat` 字段仅用于首次迁移，不删除或重写；新问答使用 `persist:false`，通过 HistoryAdapter 持久化，避免混写旧会话。没有配置 assistant-cloud，也不需要额外聊天服务器。

React 根节点在页面重建或关闭前卸载，同时取消模型请求；组件按论文／会话 ID 重新挂载，异步写入绑定原会话 ID。PDF 选区由外部订阅桥接，切换会话时清空选区。

停止按钮触发 AbortController 并销毁 HTTPS 请求。已收到的内容保存为 cancelled；网络断开、超时或截断保存为 error，供用户查看与重试。部分回答不是完整结论。

## 密钥边界

密钥由系统加密能力保存至知识库之外；正文请求头只在内存中创建。PDF 翻译密钥通过子进程 stdin 传递，不写到命令行参数或配置文件。不要复制本机加密缓存进入仓库。

## 可复现构建

先执行 `npm ci`。`python3 scripts/build.py` 调用 esbuild，把本地模块、React 和 assistant-ui 打包为一个 `main.js`，将 obsidian、electron 与 Node 内置模块保留为运行时依赖；复制样式、清单、Python worker 及依赖许可。构建不读取知识库、不读取密钥。`scripts/install.py` 必须显式指定目标知识库。

## 测试边界

离线测试通过不等于网络或 UI 可用。发布前需在隔离的演示知识库验证：导入 PDF、三个版本滚动与选择、快捷解释、首段在完成前可见、停止后保存部分内容、重试成功、主题切换与窄窗口。不要用真实私人记录制作公开截图。

## arXiv 检索与归档

搜索接口固定为 `https://export.arxiv.org/api/query`，用户输入只进入编码后的参数，不作为任意请求地址。Atom 元数据通过 DOMParser 读取为文本，拒绝 DOCTYPE／ENTITY 和 API 错误；结果链接根据已校验编号重新构造。搜索不发送私有笔记，也不读取模型密钥。请求串行，起始时间间隔至少 3.1 秒，30 秒超时，同查询合并且缓存 5 分钟，最多保留 20 组结果。

UI 保留上次结果和错误提示；页面离开后忽略过期返回。搜索结果只有点击入库才下载 PDF。arXiv 基础编号用来识别已有论文（忽略 vN）；同编号并发导入共享任务，PDF 内容哈希继续负责跨来源去重。原有记录、PDF、笔记与对话不覆盖。只有原始 PDF 缺失时，才根据新下载的相同哈希补回文件。解析完整结束后写入 PDF 与论文记录；检索摘要、主题、日期等存于 `arxiv` 字段，按全文生成的 AI 摘要仍保留在 `summary`。

## Zotero 与每日推荐

`migrate-zotero.py` 只读打开 Zotero，SQLite backup 生成快照，再解析 PDF；默认 dry-run，显式 apply 时复制附件，保留来源 metadata、目录、标签、原始笔记和批注。现有记录另作备份，原文件不覆盖；相同文件按 SHA-256 去重。同页数且完整标题或首屏文本高度一致时接入已有记录，另一份原文作为独立附件保留。中英对照只连接符合页数/宽度条件的附件；未知版本仍保留供人工检查。

`recommendations.js` 保存设置至插件数据，结果存项目目录每日 JSON。每分钟检查本地日期和更新时间；当天成功且设置未变则不重复运行。失败后一小时再试；关闭插件后不再写入结果。一次刷新共享任务锁；逐篇落盘，模型返回必须通过结构校验，不给失败结果补造分数。搜索复用 arXiv 串行限速器，按投稿日期窗口查询，按主题轮流选择有限候选。

采用 WujieHOT 五维提示词，两次独立请求的有效整数分取均值下整，另一次结构化解读返回简述、理由、局限和摘要证据信号。缓存键含基础编号、更新时间、摘要、评分版本及关键词；每次只复用最新一期已有的同键结果。评分和检索均不发送私人笔记或聊天；只有推荐候选的公开元数据进入模型。UI 读缓存，挂载不发模型请求。自动刷新与手动刷新有明确预算上限，可关闭 AI。

## 每日推荐配图

`recommendation-images.js` 独立维护按 arXiv 版本编号隔离的本地图缓存，不改变 `paper.json` 或已生成的推荐评分。HTML 只作惰性 DOM 解析，不插入页面；图片必须位于同编号的 arXiv HTTPS HTML 路径，且通过 PNG/JPEG/WebP 文件签名、尺寸和大小校验，拒绝 SVG/任意外域。按图注中的方法/架构/总览词加权，降低消融/定量对比优先级；完整单图优先，不拼凑多子图。

网页版不可用则临时加载不超过 150 MB 的 PDF，扫描前 8 页并复用 `paper-figures` 的文字/图形定位，渲染后裁出一张配图、释放 PDF 与 canvas。只保存原图裁片和来源页码，不自动归档论文，也不调用模型。网络请求排队、3.1 秒间隔、30 秒超时；并发同编号共享任务，成功缓存验证文件存在，未找到缓存一天、网络失败缓存五分钟，可手动强制重试。

卡片先预留图片空间，获取完成后只替换图片区域；切换页面后忽略旧节点返回。每日推荐完成后后台预取，已有推荐在打开页面时补齐；点击图片通过原生 Modal 放大，保留图注和原文链接。


## 知识沉淀与周期综合

`knowledge-core.js` 处理北京时间、ISO 周、调度窗口、结构化观点校验与 Markdown 写回片段；`knowledge-sources.js` 限定资料范围，保留来源类型、文本选摘和文件 SHA-256。论文仅在有摘要生成、阅读或对话活动时参与自动整理，显式选区沉淀可单独处理当前论文。未读推荐和原始剪藏正文不参与。

`knowledge-service.js` 复用论文服务的 MiniMax JSON 调用。每期单次生成、空资料跳过，失败以 error 记录；运行互斥，已写入条目或复盘不能被强制重新生成。运行记录留在项目目录。默认生成后自动发布，写回重新检查来源指纹，先持久化原稿副本与 intent，再逐文件做内容比较和原子 process 写入。每步识别已写入内容，部分失败保留计划供重试；其他编辑冲突不覆盖。只允许领域知识页、复盘、索引、日志与日记目标，不接受模型任意路径。

`knowledge.js` 注册统一导航与原生工作台视图，提供资料核对、自动沉淀阅读、可选草稿编辑、日报／周报和结构体检。日期触发检查每分钟运行，补最近已到期的一期；生成失败最多按小时追加重试两次；写入中断恢复复用原计划，不再次调用模型。autoWrite 默认启用，关闭才保留草稿。多设备无分布式锁。

结构体检与来源完整性并不验证研究事实；保留 source / inference / question 类型，不能将重复 AI 摘要作为独立证据。写回前副本是部分文件的恢复材料，不是完整 vault 备份。原始文件不修改，代码发布不携带私人运行数据。
